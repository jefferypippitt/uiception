## Why this matters

`AGENTS.md` at the repo root is the file any AI coding agent conventionally
reads first for project-specific instructions. Today it contains **only**
the output of `npx @next/codemod agents-md` — a generic index of Next.js's
own documentation pages, with zero uiception-specific guidance. The actual,
detailed conventions that govern how this repo's registry blocks are built —
folder layout, Tailwind usage rules, and the media/CDN-URL pattern — exist
instead in three files under `.cursor/rules/`, which an agent reading only
`AGENTS.md` has no way to discover. Any agent (or new contributor) relying on
`AGENTS.md` alone will miss the rules that actually matter for this
repo — e.g. the "flat layout, no nested `components/`/`hooks/`/`lib/`
subfolders for simple blocks" rule, or "always add `unoptimized` to
`next/image` for CDN block media." This fix adds a short pointer section so
`AGENTS.md` becomes a real entry point again, without discarding the
Next.js docs index (which is still useful reference material).

### The three real convention files this plan surfaces

**`.cursor/rules/registry-blocks-source-layout.mdc`** (48 lines) — defines
the shadcn-style block folder layout (`page.tsx` at root, `components/`,
`hooks/`, `lib/`, `styles/` subfolders), the equivalent installed-project
target layout, cross-block import conventions, and:
> ## Do not
> - Place components at the block root (except page.tsx)
> - Mix sub-folder files with root files
> - Add `tailwind.config.js` or `@import "tailwindcss"` inside a block folder

**`.cursor/rules/registry-blocks-tailwind.mdc`** (47 lines) — establishes
Tailwind-v4-utilities-first styling in `.tsx`, reserving block-specific
`.css` files only for keyframes/pseudo-elements/complex grids/GSAP hooks/mock-
UI scoped variables, and:
> ## Do not
> - Add `tailwind.config.js` or `@import "tailwindcss"` inside a block folder
> - Use `@apply` in block CSS for new work (prefer TSX utilities)
> - Create `components/`, `hooks/`, `lib/`, or `styles/` subfolders under a
>   block (flat layout per `registry-blocks-source-layout.mdc`)

**`.cursor/rules/registry-block-media.mdc`** (105 lines) — the CDN-URL
pattern for block images/video: hardcode CDN URLs directly in block code
(never an env var or `mediaOrigin` abstraction in shipped block code), always
add `unoptimized` to `next/image` for CDN sources so consumers don't need
`remotePatterns`, one `.gitkeep` per expected asset in `registry.json`, and a
"What NOT to do" table.

Insert this content as the **first** thing in the file, before the

```markdown
# Project conventions

Before touching anything under `registry/new-york/blocks/`, read these
project-specific rules — they are not optional style preferences, they are
enforced by `pnpm registry:validate` and reviewed in every PR:

- **`.cursor/rules/registry-blocks-source-layout.mdc`** — the required block
  folder structure (`page.tsx`, `components/`, `hooks/`, `lib/`, `styles/`)
  and import conventions between them.
- **`.cursor/rules/registry-blocks-tailwind.mdc`** — Tailwind v4
  utilities-first styling rules; block `.css` files are reserved for
  keyframes, pseudo-elements, complex grids, GSAP/scroll hooks, and mock-UI
  scoped CSS variables only.
- **`.cursor/rules/registry-block-media.mdc`** — how block images/video work:
  CDN URLs are hardcoded directly in block code (never an env var), `next/image`
  always gets `unoptimized` for CDN sources, and every expected asset gets a
  `.gitkeep` placeholder declared in `registry.json`.

After adding or editing a block, also see `README.md` ("Block structure") and
`WORKFLOW.md` (pre-push commands: `pnpm check` then `pnpm build`).

---

```

The trailing `---` followed by a blank line visually separates this new
section from the auto-generated Next.js docs index that follows.
