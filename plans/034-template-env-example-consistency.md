## Why this matters

Three docs assert that every template ships a `.env.example`:

- `CONTRIBUTING.md:27` — "Each template under `registry/new-york/templates/`
  also ships its own `.env.example` describing what that template needs once
  installed."
- `content/docs/04-template-structure.mdx:18` — folder-shape diagram lists
  `.env.example # Env vars the template expects`.
- `.cursor/rules/registry-templates.mdc` — same folder-shape expectation.

At `088cc3e` it is false for 3 of 7 templates: `portfolio-v3`, `portfolio-v4`,
`landing-page-v3` have none. Round 6 flagged this for `landing-page-v2` (fixed);
the gap just moved to the next templates. An installer of `portfolio-v3` — whose
own catalog blurb says "Drop media into public/images and public/videos" — gets
no `.env.example` at all, so no signal about what, if anything, to configure.

None of the three templates read `process.env` (verified: `grep -rn
"process.env" registry/new-york/templates/{portfolio-v3,portfolio-v4,landing-page-v3}/`
→ nothing). So each gets a short "this template needs no env vars" file, matching
the pattern `landing-page-v2/.env.example` already established. A new test then
keeps every future template honest.

### Repo conventions to match

- `.env.example` content: comment block explaining the template needs no env
  vars, then (optionally) one conventional placeholder `KEY=` with an empty
  value. Never a real value. See `landing-page-v2/.env.example`.
- New test cases: add to the existing `tests/registry/registry-templates.test.ts`
  (vitest, `describe`/`it`, `getFreeTemplateVersions()` from `@/lib/templates`,
  `existsSync`/`join` already imported there).

## Steps

### Step 1: Create the three `.env.example` files

`registry/new-york/templates/portfolio-v3/.env.example`:
```
# Portfolio v3 needs no environment variables to run. The lifeline timeline
# reads its content from lib/jon-doe.ts and resolves media locally-first from
# public/images/** and public/videos/** (falling back to uiception.com when a
# file isn't present). Replace the Jon Doe data and drop in your own assets —
# no config, no keys.
```

`registry/new-york/templates/portfolio-v4/.env.example`:
```
# Portfolio v4 needs no environment variables to run. The terminal reads its
# content from lib/portfolio.ts and lib/ascii.ts — edit those, no keys required.
```

`registry/new-york/templates/landing-page-v3/.env.example`:
```
# Landing Page v3 needs no environment variables to run. Countdown target,
# copy, and the solari-board content all live in the template's lib/ files.
# Wire up your own form/CRM backend where the template marks the stub.
```

(If the drift check showed a different set of templates missing the file, create
for those instead, with an analogous "needs no env vars" note grounded in that
template's actual content source.)

### Step 2: Declare each file in `registry.json`

For each of the three template items (`"name": "portfolio-v3"`,
`"portfolio-v4"`, `"landing-page-v3"`), add to its `files` array:
```json
{
  "path": "registry/new-york/templates/<name>/.env.example",
  "type": "registry:file",
  "target": ".env.example"
}
```
Match the placement/style of the sibling `.env.example` entries in the
`portfolio-v2` and `landing-page-v2` items (they sit alongside the other
root-target files). Change nothing else in `registry.json`.

**Verify**:
- `pnpm registry:validate` → all items valid
- `pnpm vitest run tests/registry/registry-templates.test.ts` → "declares every
  file in the template folder in registry.json" passes for all templates

### Step 3: Add the enforcement test

In `tests/registry/registry-templates.test.ts`, add a new `describe`:

```ts
describe("every template ships a .env.example", () => {
  it("has a .env.example file on disk for every catalog template", () => {
    const missing = getFreeTemplateVersions()
      .map((v) => v.id)
      .filter(
        (id) =>
          !existsSync(
            join(root, "registry/new-york/templates", id, ".env.example")
          )
      )
    expect(
      missing,
      `templates missing .env.example: ${missing.join(", ")}`
    ).toEqual([])
  })

  it("declares that .env.example in registry.json with a .env.example target", () => {
    const { items } = loadRegistry()
    const failures: string[] = []
    for (const version of getFreeTemplateVersions()) {
      const item = items.find((i) => i.name === version.id)
      const hasEntry = (item?.files ?? []).some(
        (f) =>
          f.target === ".env.example" &&
          f.path.replace(/\\/g, "/") ===
            `registry/new-york/templates/${version.id}/.env.example`
      )
      if (!hasEntry) failures.push(version.id)
    }
    expect(
      failures,
      `templates whose .env.example is not declared in registry.json: ${failures.join(", ")}`
    ).toEqual([])
  })
})
```

Confirm `getFreeTemplateVersions`, `loadRegistry`, `existsSync`, `join`, and
`root` (`registryProjectRoot`) are already imported at the top of the file — they
are at `088cc3e`. If `loadRegistry` isn't imported, add it from `./load-registry`.

**Verify**: `pnpm vitest run tests/registry/registry-templates.test.ts` → all
pass including the 2 new cases.

### Step 4: Regenerate the three registry payloads

1. `pnpm registry:build`
2. `git add public/r/portfolio-v3.json public/r/portfolio-v4.json public/r/landing-page-v3.json`
3. Revert any other `public/r/*.json` the build rewrote (unrelated line-ending
   churn is common on Windows checkouts):
   `git restore $(git diff --name-only -- public/r/ ':!public/r/portfolio-v3.json' ':!public/r/portfolio-v4.json' ':!public/r/landing-page-v3.json')`
   (or restore each individually). Final `public/r/` diff: those three only.
4. Each of the three diffs should be a single new `files` entry containing the
   `.env.example` content — no reordering, no other file changes.

**Verify**:
- `pnpm registry:validate` → all items valid
- `git status --porcelain public/r/` → only the three template payloads
