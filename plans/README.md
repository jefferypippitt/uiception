**Plan 004 Part 2 investigation findings (video budget, no code change — decision needed from maintainer):**
All 4 oversized `.mp4` files sit exactly at the compression script's
1280px/30fps thresholds, so `pnpm videos:compress` correctly no-ops on them
(confirmed live in the executor's environment, not just predicted) — getting
them under the ~2MB budget requires either trimming the ~40s clip duration
or lowering target bitrate below the script's current `-maxrate 1500k`
(~400kbps for a 2MB/40s budget), both visible-quality tradeoffs requiring a
human call. Separately, the 3-identical-video hypothesis was **confirmed**:
`google-chrome-with-video`, `mac-studio-display-with-video`, and
`macbook-pro-with-video` share byte-identical footage wrapped in genuinely
distinct device-chrome components (browser/monitor/laptop frames) —
intentional reuse consistent with the registry's self-contained-block model,
not a duplication bug.
